## 2. SCOPE OF SERVICES

### 2.1 Quarterly External Penetration Testing

Consultant shall conduct external penetration testing against Client's internet-facing infrastructure four (4) times per calendar year, scheduled as follows:

**Testing Schedule:**
- Q1: January 15-31
- Q2: April 15-30
- Q3: July 15-31
- Q4: October 15-31

**Scope Includes:**
- External network perimeter testing of all public IP ranges
- Web application penetration testing (OWASP Top 10 methodology)
- Email security testing (SPF, DKIM, DMARC validation)
- DNS and subdomain enumeration
- SSL/TLS configuration assessment
- Public cloud infrastructure review (AWS, Azure environments)
- External API endpoint security testing
- VPN gateway security assessment

### 2.2 Annual Internal Network Assessment

Consultant shall conduct one (1) comprehensive internal network security assessment per calendar year during the month of March, with duration of fifteen (15) consecutive business days.

**Scope Includes:**
- Internal network vulnerability scanning
- Active Directory security assessment
- Wireless network penetration testing
- Physical security testing (with prior written approval)
- Internal web application testing
- Database security configuration review (non-production only)
- Privilege escalation testing
- Lateral movement simulation
- Network segmentation validation

### 2.3 Social Engineering and Phishing Campaigns

Consultant shall conduct two (2) social engineering campaigns per calendar year:

**Campaign 1:** February (email phishing simulation)
**Campaign 2:** September (multi-vector campaign: email, phone, and physical)

**Scope Includes:**
- Customized phishing email templates
- Credential harvesting simulation (safe capture only)
- Telephone-based social engineering (vishing)
- Physical access attempt simulation (with 48-hour advance notice)
- Executive targeting simulation
- Awareness training recommendations
- Detailed user behavior metrics

### 2.4 Web Application Security Testing

Consultant shall perform security assessments on up to six (6) web applications per quarter as designated by Client, with minimum two (2) weeks advance notice.

**Testing Methodology:**
- Manual penetration testing using OWASP Testing Guide
- Automated vulnerability scanning (coordinated timing)
- Authentication and session management testing
- Business logic flaw identification
- API security testing
- Input validation and injection testing
- Client-side security assessment

## 4. RULES OF ENGAGEMENT

### 4.1 Testing Windows

**External Testing:**
- Permitted 24/7 for internet-facing infrastructure
- Automated scanning permitted during off-peak hours only (10:00 PM - 6:00 AM ET)

**Internal Testing:**
- Monday through Friday, 8:00 AM - 6:00 PM local time only
- No testing on Client-designated holidays
- Production database testing restricted to weekends (Saturday 12:00 AM - Sunday 11:59 PM local time)

### 4.2 Communication Protocol

**Pre-Engagement:**
- Consultant shall provide detailed testing plan five (5) business days before commencement
- Client must provide written approval via email from Dr. Vásquez or Marcus Chen
- Kick-off conference call required within 48 hours of testing start

**During Engagement:**
- Consultant shall provide daily status email by 5:00 PM ET
- Emergency contact: Consultant shall immediately call both Client security contacts for any Critical findings
- Service disruption: Consultant shall cease testing immediately and notify Client within 15 minutes

**Post-Engagement:**
- Debrief call within two (2) business days of testing completion
- Draft report delivery within five (5) business days
- Final report delivery within ten (10) business days

### 4.3 Prohibited Activities

Consultant shall NOT engage in the following without explicit written authorization:

- Denial of Service (DoS) or Distributed Denial of Service (DDoS) attacks
- Physical destruction of property
- Social engineering targeting executive leadership (CEO, CFO, CSO) without 48-hour advance notice
- Data exfiltration exceeding 10MB or containing actual regulated data (PHI, PII, PCI)
- Password cracking beyond 24-hour duration
- Exploitation of zero-day vulnerabilities without immediate disclosure
- Testing from locations prohibited by export control regulations
- Any activity that would violate HIPAA, FDA 21 CFR Part 11, or GxP compliance requirements

### 4.4 Tool Restrictions

**Prohibited Tools:**
- Metasploit "autopwn" or automated exploitation features
- SQLmap with "--os-shell" or "--sql-shell" flags against production
- Any tools causing kernel panics or system crashes
- Wireless deauthentication attacks during business hours
- ARP spoofing tools in production segments
- Tools generating >1000 requests per second without throttling

**Approved Tools (Non-Exhaustive List):**
- Nmap (with rate limiting: -T3 or lower)
- Burp Suite Professional
- Metasploit Framework (manual exploitation only)
- Nessus, Qualys, or equivalent vulnerability scanners
- Responder (passive mode only)
- BloodHound (non-disruptive collection)
- Custom scripts subject to pre-approval

### 6.1 Report Delivery Timeline

**Final Report:** Within ten (10) business days of testing completion (inclusive of feedback period)

### 6.2 Report Format and Contents

All reports shall be delivered in the following formats:
- Adobe PDF (encrypted, password-protected)
- Microsoft Word (.docx) format for Client editing
- Spreadsheet (.xlsx) with vulnerability tracking data

**Required Report Sections:**

1. **Executive Summary** (maximum 2 pages)
   - High-level findings summary
   - Risk exposure overview
   - Strategic recommendations
   - Compliance impact analysis

2. **Methodology**
   - Testing approach and standards followed
   - Tools and techniques employed
   - Testing timeline and scope
   - Limitations and constraints

3. **Technical Findings**
   - Detailed vulnerability descriptions
   - Proof-of-concept demonstrations
   - Affected systems listing
   - CVSS 3.1 scores with vector strings
   - CWE classifications

4. **Evidence**
   - Screenshots (sanitized of sensitive data)
   - Command outputs
   - Network traffic captures (sanitized)
   - Exploitation logs

5. **Recommendations**
   - Specific remediation steps
   - Prioritization matrix
   - Implementation effort estimates
   - Compensating controls

6. **Appendices**
   - Scope documentation
   - Tool configurations
   - Raw scan data (sanitized)
   - References and citations

### 6.3 Severity Classification Schema

All identified vulnerabilities shall be classified using the following schema:

**CRITICAL (CVSS 9.0-10.0)**
- Unauthenticated remote code execution
- Authentication bypass leading to full system compromise
- SQL injection with data exfiltration capability
- Complete loss of confidentiality, integrity, or availability
- **Reporting SLA:** Immediate verbal notification + written report within 4 hours

**HIGH (CVSS 7.0-8.9)**
- Authenticated remote code execution
- Privilege escalation to administrative access
- Cross-site scripting with session hijacking capability
- Sensitive data exposure (PII, PHI, financial)
- Significant business impact
- **Reporting SLA:** Notification within 24 hours

**MEDIUM (CVSS 4.0-6.9)**
- Information disclosure (non-sensitive)
- Cross-site request forgery
- Stored XSS (limited impact)
- Security misconfiguration with exploitation path
- Moderate business impact
- **Reporting SLA:** Included in draft report

**LOW (CVSS 0.1-3.9)**
- Security best practice violations
- Information leakage (minimal sensitivity)
- Missing security headers
- TLS configuration weaknesses (non-exploitable)
- Minimal business impact
- **Reporting SLA:** Included in final report

**INFORMATIONAL (CVSS N/A)**
- Observations and recommendations
- Compliance gaps (no direct exploit)
- Hardening opportunities
- **Reporting SLA:** Included in final report

### 6.4 Vulnerability Tracking

Each vulnerability shall be assigned a unique identifier using the format: **APEX-YYYY-NNNN** (e.g., APEX-2025-0001)

Consultant shall maintain a vulnerability database tracking:
- Initial discovery date
- Current status (Open, In Progress, Resolved, Accepted Risk)
- Remediation verification date
- Re-test results
